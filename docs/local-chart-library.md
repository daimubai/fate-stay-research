# 未登录本机排盘记录

当前不实现账号登录、数据库或云端保存。成功排盘后，出生信息和完整结果会保存在当前浏览器同源的 localStorage，最多 3 份。

## 页面行为

- 顶部显示“未登录 · 本机保存”。PC 侧栏展示记录名称与公历出生时间，手机默认显示当前记录摘要；通过“切换 / 管理”展开记录和重命名、删除操作，“＋ 新增”进入新排盘。
- 每次成功计算自动保存完整快照（含公历/农历、四柱、十神、藏干、五行、纳音、长生、神煞、胎元两宫、起运、大运、流年以及引擎/规则版本）。切换记录直接恢复输入与结果，无需重新请求后端。
- 同一公历出生日期、分钟及性别作为一份记录的标识；等价的公历/农历输入更新同一位置，保留自定义名称。
- 满 3 份时不自动淘汰。当前结果仍可查看，用户可明确替换某份记录，或“暂不保存”。记录区会提示未保存，并提供保存或替换入口。
- 结果区也提供快捷切换按钮，便于比较不同出生时间。每份记录都有当前选中状态。
- 重命名最多 20 字。删除前做行内确认；删除当前保存记录不会清空已显示的计算结果，可手动重新保存。
- 刷新页面恢复上次查看的记录及结果。点击“＋ 新增”后刷新保留未选中记录的状态，原有记录仍在。
- 修改出生信息会清除旧结果，成功重算后再更新记录；不能把旧排盘误存到新的出生日期上。切换记录会使过期的计算请求结果失效。

## 存储与边界

存储键：`fatestay.guest-charts.v1`，结构为 `{version:1, records:[...], activeId}`。记录包含 `id`、`name`、`birth`、`chart`、`savedAt`。数据为本地明文，不进行账号同步；清除网站数据、换浏览器或换来源（域名/端口）不会保留或共享同一份缓存。

读取时校验结构、日期范围、出生时间与结果对应关系、详解字段、藏干及五行统计，跳过损坏/不完整/重复记录，恢复有效项并限制最多 3 份。不兼容格式会提示重新排盘，不让旧快照使页面报错。

浏览器禁止存储或配额不足时继续允许排盘与本页内切换，提示本次变更可能无法跨刷新保留。已加载页面中切换快照不依赖网络；这不等于提供离线网站安装或离线计算。

存储读写通过 `LocalStoragePort` 与界面隔离，保存/重命名/删除为独立函数。后续账号与数据库功能可以增加存储适配器和迁移流程，本次不会创建后端记录接口或自动上传历史记录。

## 验证

`cd frontend && npm test`：截至 2026-11-04，前端共 25 项测试通过。本机记录测试覆盖快照隔离、公农历去重、3 份上限、显式替换、刷新序列化、删除、重命名、损坏和超大缓存、不兼容详解、禁用/满额存储及响应式代理快照。

浏览器实测覆盖成功排盘自动保存、满额提示、暂不保存/重试、结果区快捷切换、重复计算不增位、刷新恢复、离线切换、删除和重新保存、损坏缓存和配额拒绝的降级；PC 1280px、手机 390px 下检查展示和交互。

## 性别与历史快照兼容

当前记录 id 追加 `|MALE` 或 `|FEMALE`，同刻男女分别占位。旧版没有性别/运程的记录仍然可查看，不擅自默认性别；页面提示选择性别重新排盘。首次明确选择后重算，会优先升级对应旧位置并保留名称，不额外占位。

存储键和版本保持兼容，新增字段做条件校验：有性别必须有完整的 10 步大运和各 10 个流年，且年份/年龄递增；无性别的旧快照只展示原四柱详解。新增运程快照仍可刷新恢复、离线在已打开页面切换。

流月/流日通过独立接口按需加载，不扩充本机记录快照。刷新或离线切换记录后，未在当前页面载入的明细需要后端连接；已保存的四柱详解、大运和流年快照仍可查看。

流时同样按需加载，仅在同一排盘联动区域内存缓存最多 24 份，不修改本机排盘快照。首次查看未加载流日的时辰需后端连接；节令截断流日仍展示十二时辰参考，但区间外无实际覆盖时间。

十二长生与神煞的新字段、规则及旧缓存兼容见 [计算说明](natal-traits.md)。

胎元、命宫、身宫的 `auxiliaryPalaces` 随出生排盘快照一同缓存。旧记录缺该字段时正常显示并提示重新排盘，同一出生信息重算保留原槽位与名称；新字段存在时必须包含全部三项完整结果。详见 [计算与兼容说明](natal-palaces.md)。

紧凑工作台将记录移至 PC 左侧，手机默认仅显示当前记录摘要，点击“切换 / 管理”展开记录与操作。重命名、删除、满额替换和未保存结果的手动保存入口仍保留。切换本机排盘会重置时间选择上下文；流月/日/时不会自动请求，打开对应选择器时再按需载入。

四柱关系 `relations` 随出生快照缓存，旧记录缺该字段仍可读，重算更新原位置；新字段存在时校验版本、七类目录、形态、唯一 ID 及参与者和原四柱的对应关系。展开、筛选或标记关系只使用快照，不请求运程数据。详见 [关系与兼容设计](pillar-relations.md)。
